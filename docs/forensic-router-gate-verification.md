## 2. Which Models Were Skipped and Why

**None.** Across both real runs, the new capability gate emitted **zero**
`[skip] custom:* / ... — skipped (prompt Xt > Yt limit)` lines. Reasons:

- Discovery hardcodes `context_window: 128000` for every custom model
  (`custom-endpoint-provider.ts:198`), ignoring the host's real per-model value
  (Groq reports gpt-oss-120b `context_window: 131072`).
- Gate ceiling for custom:* = `floor(128000 * 0.25)` = **32000 tokens**.
- `estimateRequestTokens()` = `ceil(chars/4) + 100` — a prompt must be
  **> 128,000 characters** (~32k tokens) to exceed the ceiling.
- Real code-gen prompts (system + user) are ~30–60 KB → estimate ~8–15k tokens,
  **far below 32000** → the gate never fires on real workloads.

**Consequence:** the exact failure the gate was meant to prevent — an oversized
request hitting a custom:* provider — still occurred: `openai/gpt-oss-120b`
returned **HTTP 413 "Request too large"** 3× in Run A. The gate is effectively
**inert** for realistic prompts given the hardcoded 128k context_window.

## 12. Exact Remaining Blockers

1. **Gate is inert on real workloads** — `context_window` hardcoded to 128000 in
   `custom-endpoint-provider.ts:198` makes the custom:* ceiling 32000 tokens;
   real prompts (~8–15k estimated) never trip it. Oversized requests (HTTP 413
   from gpt-oss-120b) still reach custom:* providers. The 25% fraction needs a
   per-model or realistic ceiling to actually filter.
2. **LLM code hallucination** — llama-3.3-70b-versatile emitted non-compiling
   imports (`zod` `validate`, `better-sqlite3` named import, type-as-value). JSON
   extraction passes, but generated code fails `tsc`/build; the phase repair loop
   did not fix it, and the frontend then fell back to templates.
3. **package.json scripts** — LLM scaffold omitted `lint`/`typecheck`/`test`;
   `validateGeneratedProject` (orchestrator:3507) blocks the pipeline. Template
   scaffold (line 1100) includes all six; the LLM override dropped them.
4. **429 rate limiting** on llama-3.3-70b-versatile — only working model; phase 3
   exhausted its single retry, forcing template fallback.
5. **Brand/idea incoherence** — "Siftline" idea vs "Forge" project name; empty
   criteria/sponsors; generic bug-diagnostic UI unrelated to the VoltHacks theme.
6. **Pre-existing (out of scope):** provider-integration test failure
   (`custom` provider registration order); `providers.ts`/`provider-types.ts`/`scripts/*`
   build errors; OpenRouter fallback disabled by missing env key.

## Bottom Line

The new capability gate is **correctly placed** (before `provider.execute()`,
type-clean, unit-tested, NVIDIA unchanged) but **does not fire on real oversized
prompts** because `context_window` is hardcoded to 128k in discovery, so the
`custom:*` ceiling (32000t) exceeds every realistic request. The 413 that the gate
was built to prevent still reached `custom:groq/gpt-oss-120b`. Generation is
**PARTIAL LLM**: LLM produced broken backend code; templates produced the UI; the
pipeline blocked at build because the LLM's package.json/imports don't compile.
No fixes were applied per instructions.
